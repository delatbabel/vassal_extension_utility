> That's a good point. We could dispense with the XOR'ing entirely. The only purpose it ever had was to make the save data be other than plain text if you unzipped a save file. `ObfuscatingOutputStream` could be deprecated.

Done. The `savedGame` entry is now a plain XZ stream of the command log — nothing in front of it, nothing XORed — recognised on the way back in by XZ's own magic bytes. `GameState.compressSavedGame(OutputStream)` is the one place a save or log is compressed (`saveGame`, `saveGameRefresh`, `BasicLogger.write` all use it); `DeobfuscatingInputStream` reads the XZ stream, the released `!VCSK` hex form, and plain text. `ObfuscatingOutputStream` is `@Deprecated(forRemoval = true)` and reduced to a wrapper that compresses the same way, so anything still constructing one writes a readable file; its XOR code, headers and key are gone, and `ObfuscatingOutputStreamTest` with them. The `DeobfuscatingInputStreamTest` cases now cover the XZ stream (magic, whole and byte-by-byte round trips, truncation, repetitive text shrinking) and the deprecated wrapper producing the same bytes.

Verified again on the 7 072-piece game: the engine writes an 829 KB file, which the extension utility (which reads this form too now) rewrites to a byte-identical log, and the engine loads that and saves it to an identical log again.

#15117 has dropped its small change to `ObfuscatingOutputStream` (a block XOR) so it no longer touches the class; its writers keep constructing one, which the deprecated wrapper covers, and switch to `compressSavedGame` once both are in.
